## 1. 对抗样本、数据投毒和后门攻击的区别与适用场景

- 对抗样本攻击：
  - 本质：发生在测试/推理阶段，通过给输入样本加入人眼难以察觉的扰动，使模型产生错误判断。
  - 特点：不改变训练数据和模型参数，只攻击模型输入。
  - 适用场景：攻击者能直接控制或修改输入，例如图像识别、语音识别、自动驾驶感知系统等。

- 数据投毒攻击：
  - 本质：发生在训练阶段，通过向训练集中注入恶意数据，影响模型学习过程。
  - 特点：目标通常是降低模型整体性能，或让模型在某些类别上产生偏差。
  - 适用场景：训练数据来源不可信，例如公开数据集、众包标注数据、联邦学习场景等。

- 后门攻击：
  - 本质：通常发生在训练阶段，攻击者在模型中植入特定触发器，使模型在正常输入下表现正常，但遇到触发器时输出攻击者指定结果。
  - 特点：隐蔽性强，平时难以发现，只有触发条件出现时才表现异常。
  - 适用场景：攻击者能影响训练数据、预训练模型或模型供应链，例如使用第三方模型、外包训练服务、下载开源权重等。

## 2. 白盒模型后门检测和黑盒模型后门检测的优缺点与适用场景

- 白盒后门检测：
  - 含义：检测者可以访问模型结构、参数、梯度或中间层激活信息。
  - 优点：可利用模型内部信息进行分析，检测更深入，准确率通常更高。
  - 缺点：需要较高权限，现实中不一定能获得完整模型信息。
  - 适用场景：自有模型安全审计、开源模型检查、企业内部模型部署前检测等。

- 黑盒后门检测：
  - 含义：检测者无法访问模型内部，只能通过输入样本并观察输出结果来判断是否存在后门。
  - 优点：不依赖模型内部信息，更接近实际攻击与使用场景。
  - 缺点：检测精度通常较低，查询成本较高，隐蔽后门容易漏检。
  - 适用场景：第三方 API 模型、云端模型服务、无法获取源码或权重的模型检测等。

## 3. 如何提前预防后门攻击对模型可用性和完整性的破坏

- 保证训练数据可信：
  - 对训练数据进行来源审查，避免直接使用来源不明的数据。
  - 对数据进行清洗和异常样本检测，减少恶意样本混入的可能。

- 加强训练过程防护：
  - 使用数据增强、鲁棒训练和正则化方法，降低模型学习异常触发特征的风险。
  - 在训练过程中监控异常损失、异常梯度和异常激活现象。

- 控制模型供应链风险：
  - 尽量使用可信来源的预训练模型和开源权重。
  - 对第三方模型进行安全评估后再部署，避免直接上线未经验证的模型。

- 部署前进行安全检测：
  - 在模型上线前进行后门扫描和异常行为测试。
  - 构造不同输入模式，检查模型是否存在特定触发条件下的异常输出。

## 4. 已检测出恶意后门后的补救措施

- 使用干净数据微调：用可信、干净的数据重新微调模型，可以削弱模型对后门触发器的依赖。
- 剪枝可疑神经元：分析模型中异常激活的神经元，并进行剪枝处理。
- 输入过滤与触发器检测：在部署阶段检测输入中是否存在可疑触发器，对异常输入进行拒绝、清洗或人工复核，减少后门被触发的机会。
- 模型回滚或替换：如果后门影响严重，且难以确认是否完全清除，应回滚到可信版本或更换模型。
- 重新训练模型：在确认训练数据可信的前提下重新训练模型，可以从根源上消除后门影响。
