# Homework 4

## **1.**⽩盒模型逆向攻击和⿊盒模型反演攻击各适⽤于什么样的场景？课程中的模型逆向攻击都需要最终的输出向量，是否有可能进⾏仅获得标签的模型逆向攻击？

### （1）白盒模型逆向攻击适用场景

白盒模型逆向攻击适用于攻击者能够获得模型内部信息的场景，例如模型结构、参数、梯度、中间层特征或损失函数等。攻击者可以直接利用这些信息优化输入，使模型对某一目标类别输出较高置信度，从而恢复该类别的典型特征或近似训练样本。

典型场景包括：

- 科研测试中研究者拥有完整模型，用于评估隐私泄露风险；
- 开源模型权重被公开后，攻击者可以直接下载并分析；
- 内部人员或供应链泄露导致模型参数被获取；
- 联邦学习中攻击者通过梯度或参数更新进行样本重建。

例如，在人脸识别模型中，若攻击者获得模型权重和梯度，就可能通过优化输入图像恢复某一身份类别的典型人脸特征。白盒攻击信息充分，攻击效果通常较好，但现实中完整获得模型内部信息的难度较高。

### （2）黑盒模型反演攻击适用场景

黑盒模型反演攻击适用于攻击者不能访问模型内部，只能通过查询接口获得输出的场景。攻击者根据输入与输出之间的关系，不断构造查询样本，推断模型对某些类别或敏感属性的内部表示。

典型场景包括：

- 商业机器学习 API，例如人脸识别、医疗诊断、语音识别等；
- 云端模型服务，用户只能提交输入并获得预测结果；
- 攻击者希望通过返回的概率向量或置信度恢复某一类别的典型样本特征。

例如，在商业人脸识别 API 中，攻击者无法访问模型参数，只能通过反复提交图像并观察返回结果来推断目标类别特征。黑盒攻击更符合现实场景，但由于信息有限，往往需要更多查询，攻击成本也更高。

### （3）仅获得标签是否可能进行模型逆向攻击

仅通过标签进行模型逆向攻击在理论上是可能的，但难度明显更高。因为模型只返回最终类别，攻击者无法获得完整概率向量，也就缺少连续的优化信号。

可行思路包括：

- 通过决策边界搜索，观察标签变化来逼近目标类别区域；
- 使用进化算法或随机搜索，根据标签反馈不断生成更接近目标类别的样本；
- 借助 GAN、扩散模型等生成模型先验，在自然图像空间中搜索；
- 先训练替代模型，再在替代模型上进行白盒式逆向攻击。

但这种方法存在明显限制：查询次数多、反馈信号弱、优化不稳定，且通常只能恢复目标类别的原型特征，难以精确恢复真实训练样本。因此，仅标签逆向攻击是可能的，但实际攻击成本较高，效果通常弱于基于完整输出向量的攻击。

## **2. 模型窃取攻击中，替代模型⽅法异常的⼤量查询不仅仅会增加窃取成本，更会被模型拥有者检测出来，你能想到什么解决⽅法来避免过多的向⽬标模型查询?**

### **（1）主动学习式查询**

可以使用主动学习减少无效查询。攻击者先用少量查询训练一个初始替代模型，再在本地生成大量候选样本，只选择替代模型最不确定、最接近决策边界或最能提升模型性能的样本去查询目标模型。

这种方法的原理是提高单次查询的信息量，而不是盲目增加查询数量。例如，对于分类任务，可以优先查询预测熵较高的样本，因为这类样本对学习目标模型决策边界更有价值。

可行性方面，主动学习能够有效减少查询次数，并降低被检测概率。但它依赖初始替代模型的质量，如果初始模型很差，选择出的样本可能并不真正有效。

### **（2）利用公开数据和预训练模型**

攻击者可以使用公开数据集、预训练模型或相似任务模型作为先验，从而减少对目标模型的依赖。例如，对于图像分类 API，可以使用公开图像数据构造查询样本，并用预训练模型初始化替代模型，只对关键样本查询目标模型进行微调。

这种方法可行性较高，特别适用于目标任务与公开数据分布相似的场景。但如果目标模型处理的是高度专用的数据，例如医疗影像、金融风控或私有工业数据，公开数据与真实分布差异较大，效果会下降。

### **（3）数据增强与半监督学习**

对已经查询过的样本进行旋转、裁剪、加噪声、颜色扰动等数据增强，可以扩充训练集而不增加查询次数。也可以使用半监督学习，用少量目标模型标注样本训练替代模型，再让替代模型为大量未标注样本生成伪标签。

这种方法能够降低查询成本，但标签一致性假设不一定总成立。如果增强后的样本语义发生变化，或者伪标签错误较多，替代模型性能会受影响。

综上，避免过多查询的主要方法是：主动学习提高查询价值，公开数据和预训练模型引入先验，数据增强和半监督学习扩大本地训练数据。这些方法可以降低窃取成本和异常查询风险，但无法完全消除对目标模型的查询需求

## **3. **在**MemGuard**的防御场景下，如果攻击者在输⼊图像上添加扰动可以破坏单次随机的设定你认为防御者应该如何应对?

### **（1）采用一致性随机化**

如果攻击者通过对输入图像添加扰动，多次查询相似样本来破坏单次随机设定，防御者可以将单次独立随机扰动改为一致性随机化。也就是说，对于同一个输入或高度相似的输入，系统应返回相同或相近的扰动输出。

具体可以通过鲁棒哈希、输入特征聚类或相似度匹配，将相似图像映射到同一个随机种子。这样攻击者即使多次提交轻微扰动后的图像，也无法通过统计平均消除随机噪声。

### **（2）检测相似查询和异常查询行为**

防御者可以记录用户查询历史，检测是否存在大量相似图像被反复提交的情况。对于图像任务，可以使用感知哈希、特征空间距离或嵌入相似度判断输入是否属于同一邻域。

如果发现异常行为，可以采取：

- 限制查询频率；
- 只返回标签，不返回置信度；
- 对可疑用户增强输出扰动；
- 对相似输入统一缓存返回结果；
- 对异常账号进行验证或封禁。

这种方法适合部署在商业 API 中，因为服务端可以监控查询模式。

### **（3）使用鲁棒防御优化**

防御者还可以在防御设计中考虑输入扰动，使 MemGuard 不只对单个输入点有效，而是对其邻域内的一组相似输入都有效。也就是说，在生成防御扰动时，同时考虑原图及其扰动版本，让相似输入的防御输出保持一致。

这种方法可以提高防御稳定性，但会增加计算开销，并可能影响正常模型输出质量。

因此，防御者应采用组合策略：一致性随机化、相似查询检测、输出信息降级、查询限制和鲁棒防御优化。其局限在于可能误伤正常用户，也可能被分布式账号或更隐蔽的查询方式绕过。

## **4. **数字⽔印可以保护模型版权，但是⽆法防御攻击者窃取模型的过程，是否有⽅法可以直接防⽌模型被窃取?

### **（1）限制输出信息**

可以通过减少模型 API 返回的信息量来防止模型被窃取。模型窃取依赖输入—输出对，如果 API 返回完整概率向量，攻击者可以获得丰富的软标签信息，更容易训练替代模型。

防御方法包括：

- 只返回 top-1 标签；
- 只返回 top-k 结果；
- 不返回完整置信度；
- 对概率值进行四舍五入或区间化；
- 对输出加入适度噪声。

其原理是降低每次查询的信息量，使攻击者更难拟合目标模型的决策边界。

### **（2）查询监控与异常检测**

模型拥有者可以监控用户查询行为，识别模型窃取攻击的典型模式。例如，短时间内大量查询、输入分布异常、大量样本靠近决策边界、同一账号覆盖大量类别等，都可能说明存在窃取行为。

一旦发现异常，可以进行限流、降低输出精度、要求身份验证、临时封禁或人工审核。这种方法在商业 API 场景中较为可行。

### **（3）访问控制与速率限制**

还可以从系统层面提高窃取成本，例如设置 API 调用上限、用户认证、分级权限、付费门槛、IP 限制和设备指纹识别等。虽然这些措施不能从理论上完全阻止模型窃取，但可以显著增加攻击者大规模收集数据的难度。

### **（4）动态输出与模型随机化**

防御者还可以使用动态模型或输出随机化，使攻击者难以通过查询学习到稳定的目标函数。例如，对不同用户使用略有差异的模型版本，对可疑查询返回降级结果，或在边界附近加入受控随机性。

这种方法能增加窃取难度，但如果随机性过强，也可能影响正常用户体验。

综上，数字水印主要用于事后版权证明，不能直接阻止窃取过程。更直接的防御方法包括输出信息限制、查询监控、访问控制、速率限制和动态输出。这些方法无法保证模型绝对不会被窃取，但可以显著提高窃取成本、降低替代模型质量，并提高攻击被发现的概率。因此，从严格意义上说，只要模型仍然对外提供预测服务，就很难完全阻止模型窃取；更现实的目标是降低输出信息量、限制查询规模、提高攻击成本，并在异常行为出现时及时检测和阻断。
